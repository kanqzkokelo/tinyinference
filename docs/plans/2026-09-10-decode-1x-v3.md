## Work queue (ordered by expected gain)

### W1 — Land Q8-KV hybrid (IN PROGRESS, uncommitted)
Change (`kernels/qwen2_cuda.cu`): Q8 KV default-ON with hybrid
threshold default 256 — FP32 below (short-ctx gates stay bit-identical),
Q8 above (long-ctx gets the 4x KV traffic cut).
Opt-out `TT_Q8_KV=0` / `TT_KV_F16=1`; `TT_Q4_KV` still
overrides; `TT_QKV_THRESH` tunes crossover.

Why hybrid not plain default-ON: plain Q8 default-ON failed the logit
gate 0/7 (median dlogit 0.25-1.0 vs 0.15 gate) while FP32 passed 7/7.
Hybrid keeps the FP32 acceptance baseline for short ctx and buys the
measured long-ctx wins (qwen3-2048 +66pct, smol-2048 +14pct in micros).

Validation order before commit:

1. Build clean (mmcuda nvcc, sm_86).
2. `./scripts/verify.sh m61` — must pass (short ctx stays FP32).
3. Clean greedy-prefix rerun all four primaries, Q8 OFF vs hybrid-ON at
   short ctx: must be identical (prior probe showed a qwen2.5 divergence
   needing a clean rerun to confirm/deny; qwen3/smol/llama matched).
4. Long-ctx decode bench (qwen3-2048, smol-2048, llama-512): expect
   qwen3-2048 large gain, smol-2048 moderate gain, llama-512 neutral.
5. Commit separately from any other change.
